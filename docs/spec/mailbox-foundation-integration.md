# Mailbox foundation integration specification

## Goal

This proposal synthesizes source audits replay-topics-source-audit, local-console-source-audit and interop-framework-source-audit fetched through CLEO on 2026-09-30. It specifies mailbox transport and observability only. MUST/MUST NOT are normative implementation targets; none imply features already shipped. CLEO remains task/evidence authority. No remote task executor, autonomous orchestrator, broad cloud console or framework dependency is introduced.

## Requirements

### Replay and history

A durable per-mailbox visibility ledger MUST assign a monotonic sequence when mail first becomes visible to that mailbox. Message creation order is insufficient: late remote receipt, late recipient insertion and rename transfer MUST each receive current visibility order. `(mailbox,message_id)` deduplication MUST avoid duplicate replay for locally sent-and-received mail. Snapshot pages MUST capture high-water mark and select rows inside the same SQLite read transaction, order ledger sequence ascending, filter authorized visibility before LIMIT, freeze the high-water mark for finite traversal and enforce default 50/max 200 entries plus a byte budget. Query execution MUST also bound scan batches. Cursor scan position MUST progress over filtered/now-hidden entries even on an empty returned page; output MUST not expose foreign IDs/counts. At the boundary, finite traversal reports no more and the next poll captures a new snapshot. A first oversized visible message MUST return deterministic bounded metadata `{id,content_omitted:true,reason:"REPLAY_ITEM_TOO_LARGE"}` and advance that entry; its body is available through existing explicitly requested read. Later byte-budget exhaustion stops before the next visible entry so it is retried on the next page. Never repeat an empty unchanged cursor indefinitely. Sender timestamps, lexical IDs and unstable rowid MUST NOT define live resume order.

First release SHOULD expose `mbx_replay({cursor?,limit?,project?,topic?,thread?}) -> {messages,next_cursor,has_more}` with no server checkpoint mutation. Cursor MUST be a versioned base64url JSON pagination frame treated as untrusted input, bound to store epoch, mailbox, normalized filter identity and snapshot boundaries; it MUST NOT authorize reads. No MAC secret is required in the first contract: every field MUST be validated (finite safe integers, ordered bounds, supported version, current epoch, exact current mailbox/filter and maximum frame size) and lease/visibility reauthorized independently. Tokens MUST contain no body, credential or plaintext project path; a normalized filter digest is sufficient. Authorized callers can explicitly choose/reset a position; no-skips applies to following returned continuations, not intentionally selecting a later position. A malformed/out-of-bounds frame MUST fail, never fall back to a global query. The caller explicitly supplies the prior next_cursor after observing the response. Reusing an input cursor MUST reselect the same ordered event range while visibility remains unchanged; deleted/revoked mail MUST never be restored merely to reproduce a response. IDs permit duplicate-safe handling. Lost response retries the original input cursor; there is no automatic advance. All calls MUST revalidate the actual mailbox lease. Cursor scope binds the mailbox persona, not lease token or provider thread: a newly authorized holder of the same name MAY resume its old token; rename/different name MUST reject scope. Delivery states and wakes MUST remain unchanged.

Durability means ledger and cursor verification survive process/provider restarts; automatic restoration of agent context is a separate concern. Agents SHOULD preserve the token in a handoff/CLEO reference; loss means safe replay from beginning. Named server-side consumer checkpoints and extra RPCs SHOULD be deferred unless workflow validation proves needed. If added, explicit observation confirmation and CAS versions MUST protect concurrent advancement; default replay stays read-only.

A completed finite snapshot's continuation MUST start after its final boundary on the next poll. Membership/filter changes MUST NOT reuse an old cursor: changed filters return CURSOR_SCOPE_MISMATCH and start a fresh explicit history scope. Joining a project/topic MUST NOT reveal undelivered mail. Authorized historical catch-up MUST create recipient visibility events above existing cursor positions. Rename-generated destination grants MUST emit events, including already-stored message IDs; release/claim name switches MUST NOT carry cursors or mail across identities.

Cursor errors MUST distinguish CURSOR_INVALID, CURSOR_SCOPE_MISMATCH and CURSOR_EXPIRED without exposing foreign mailbox IDs/counts. No automatic retention/deletion in initial release. Later pruning MUST maintain tombstone/floor semantics and explicit expiration recovery. Migration MUST backfill visible pairs deterministically under existing canSee host/origin rules, preserve signatures/ACK state and increment schema version so old writers fail closed. Ledger insertion MUST share the actual transaction that creates sender or recipient visibility. Every writer MUST be covered: Store.insertMessage/addDelivery, local send/remote receive and node.addAlias direct destination delivery SQL, with process coverage for MCP whoami calling leases.rename then addAlias. Source budgets MUST NOT omit writers. Correction from qualified caller inspection: normal MCP whoami invoke uses leases.withHeld -> withObserved -> Store.tx; leases.rename and node.addAlias nested savepoints share that outer transaction. The MCP rename path SHOULD therefore roll back both lease and mail on transfer failure, and a process-level injected failure MUST prove that behavior. Standalone calls to lease rename and alias transfer made separately do not imply joint atomicity. Current pair uniqueness assumes no revocation/regain feature; future regain MUST emit a new event or explicitly reject unsupported regain. Restored DB copies also restore internal epochs, so explicit restore/reset MUST rotate epoch or supply external generation proof; automatic rollback detection cannot be inferred from restored contents alone. The operational restore sequence MUST stop daemon/connectors/writers, preserve backup, restore coherent DB, rotate epoch through a scoped replay-reset command/control before reopening service, then reject old-generation frames. No CLI restore feature is claimed shipped; R2 MUST provide the reset primitive and tested operator invocation before restore safety is claimed.

Existing FTS SHOULD power handoff search. Project/topic/thread/kind/time filters MUST apply before result limits, stay indexed and leave signed envelopes unchanged. The existing signed project path is host-local: first increment supports exact `(sender_host,project_path)` filtering. Portable project IDs require explicit host-root mappings. Topic names MUST be scoped to portable project IDs and remain classification, not permission. Handoff status/decision messages SHOULD carry a documented tag, task references and session/receipt links; neither tags nor handoff prose transfer lease or authority.

## Diagnostics and local console

One versioned read-only diagnostic adapter MUST serve CLI and console, using exact-session/mailbox selectors, bounded pages and timestamps. Installed CLI, daemon and observed connector versions MUST remain separate. Unknown runtime version/process birth is null plus reason, not inferred from CLI version. Ownership states held/available/unknown/legacy/conflict MUST retain conservative recovery behavior. Pending receipts MUST remain pending until actual control results are observed; snapshot reads MUST NOT finalize uncertain writes.

Delivery accepted locally, destination delivered, notified, read and acked MUST remain distinct from processed/completed tasks. Outbox attempts/next retry and sanitized error classes SHOULD be visible. DTOs MUST omit private keys, grant/control/lease tokens, environment values and unfiltered process args/errors. Agent scope MUST NOT expose another mailbox's body or private diagnostics. Owner scope means an explicit same-OS-user CLI console launch, not Touch ID/cryptographic owner-signing authentication. The browser boundary protects against remote/cross-origin access; it MUST NOT claim protection from arbitrary same-user shell agents that already have local DB/file access. Agent MCP APIs remain mailbox-scoped and MUST NOT provide global console capabilities. Diagnostic generation is a sanitized public opaque identifier, not control key/token or credential hash.

Console MUST use a separate loopback-only ephemeral listener, never private routes on the LAN host listener. Launch MUST create a bounded short-lived read-only capability. Browser fragment bootstrap exchanged by same-origin POST SHOULD issue HttpOnly SameSite=Strict cookie and immediately remove fragment; secrets MUST NOT enter query strings/logs. Initial navigation GET naturally lacks Origin and MAY load only the nonprivate app shell under exact Host; bootstrap POST MUST require exact Origin plus one-use launch capability. Private native calls without Origin require explicit capability, not automatic cookie trust. Mail MUST render as escaped text without remote image/Markdown execution. Exact Host/Origin checks, no permissive CORS, no third-party assets, CSP self/no framing and no-store private responses are required. Agent tools MUST NOT mint owner console capabilities. First UI has identity/runtime, selected mailbox/thread/search and delivery/receipt views; no mutation buttons. Refresh SHOULD be bounded polling with visibility-aware backoff. SSE is later measured invalidation only, with bounded/coalesced queues and reconnect resnapshot; it is not durable replay.

## Discovery and CLEO alignment

Native signed cards MUST precede discovery projection. A local preview MUST be labeled native capability metadata/A2A-inspired preview, not a conforming public AgentCard with invented required interfaces or execution URL. A local preview MAY export bounded description, explicitly advertised skills/media, provenance, expiry and supported protocol metadata. Capability descriptions MUST NOT grant tools/policies/subscriptions. A2A execution interfaces MUST NOT be advertised without conforming endpoints. Imported cards MUST be size/schema/expiry bounded, trust-labeled and incapable of URL fetching, authority creation or execution. No automatic endpoint probing; network gateway is outside this release.

CLEO integration MUST use immutable authenticated principal separately from mutable mailbox persona. Accepted/delivered/acked MUST map to transport only. Task completion requires independent CLEO-authorized evidence and MUST NOT follow from payload.taskId or mbx_ack. Future projections MUST carry project/task ID, event ID, source revision and authority provenance with deterministic duplicate handling. Existing experimental transport TODOs are blockers, not compatibility guarantees.

AutoGen ideas adopted: typed correlation IDs, explicit scoped topic matching, bounded waits and cooperative wait cancellation. Canceling a wait MUST NOT delete/ack mail, release a lease or cancel a CLEO task. No Python runtime/framework is imported. AgentChatBus view models and connection cleanup are presentation ideas; its role/system prompt machinery is not authority.

## Verification matrix and performance gates

Every slice MUST prove unchanged ACK/lease/privacy semantics with focused tests. macOS arm64/x64 and Linux arm64/x64 CI builds and SEA smoke remain release gates. Codex/Claude/OpenCode exact-session restart and provider-switch tests are required for replay consumers; Kimi/Hermes require supported adapter fixtures and explicit coverage gaps rather than assumed parity. Windows is unsupported until process-birth/private-file/install evidence exists; no Unix-only new API contract should require a socket path.

Replay fixtures MUST cover timestamp collisions/clock skew, delayed LAN arrival, duplicate receipt, late recipient/topic catch-up, rename destination expansion, same-input retry, lost response, concurrent writers, fenced holder, occupied mailbox and filter mismatch. Diagnostics tests MUST cover two sessions, stale connector version, PID reuse/unknown evidence, secret redaction and no side effects. Console tests MUST deny unauthenticated LAN/wrong Host/foreign Origin/expired capability and preserve delivery state while browsing. Discovery fixtures MUST reject expired/tampered/unsupported cards and omit execution capability. CLEO tests MUST separate ACK from completed work.

Measure 10k/100k/1m-message fixtures, sparse/skewed recipients, large bodies and concurrent MCP/daemon writers. Capture p50/p95 page latency, rows inspected/query plans, response bytes, migration storage/time, WAL growth and lock contention. Deep keyset pages MUST avoid work proportional to prior page offset. Exact latency thresholds MUST derive from T119 baseline, not invented promises; compare regressions with equal fixture/hardware. No source audit executed competitor runtime benchmarks.

## Non-Goals

Remote task execution, autonomous orchestration and framework import are excluded.

## Out-of-Scope

Automatic checkpoint advancement, subscription routing, remote console hosting and public A2A execution endpoints are deferred.
