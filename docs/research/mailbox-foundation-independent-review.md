## Question

Are source-derived replay, diagnostics, console and discovery contracts ready for bounded implementation without private-mail leaks, skipped events or invented task completion?

## Findings

The design is sound with clarifications below. Approve independent implementation of measured SQL improvements and diagnostic adapter after safe migration/selector tests. Approve replay foundation only after exact insertion coverage and boundary behavior are specified. Console/capability export remain later slices with their own explicit authorization and packaging gates. No framework dependency or third-party code is required.

1. Visibility ledger is the correct minimum alternative to cursor by message timestamp/ID. Ledger insertion MUST share the actual message/delivery visibility transaction. Existing node.ts addAlias inserts destination deliveries and deletes old unacked rows; mcp.ts calls leases.rename then addAlias separately. Source currently has no delivery direct SQL in mcp.ts; an earlier concern suggesting that was corrected. Inspect/test this caller rather than adding a fourth source file by assumption. Lease/mail rename failure semantics remain unchanged unless explicitly improved with joint transaction. Source/test budgets MUST NOT omit a necessary writer.
2. First-visibility UNIQUE(mailbox,message) dedup is adequate for current no-retention/no-regrant scope. Future authorization revoke/regain cannot silently reuse an earlier skipped sequence: define new visibility event or forbid unsupported regain. Ledger entries MUST be rechecked against current canSee; stale old-name entries after rename never confer authority.
3. Snapshot highwater and row selection MUST share one SQLite read snapshot. Cursor progresses over examined filtered/nonvisible entries, not only returned rows, and has_more must reflect authorized scope. Completed snapshot continuation starts after highwater; messages committed after capture arrive next poll. Oversized first visible envelope needs explicit error/metadata with bounded response and deterministic continuation; never repeat an empty page indefinitely. No automatic ACK, delivery-state change, lease expiry, receipt finalization or server checkpoint write.
4. Persisted cursor verifier secret must survive legitimate process/provider restart. Cursor scope is mailbox, not holder session: same name new authorized lease may resume; rename or different name rejects. Token is not authorization and must not contain private body/project data in exposed plaintext. Restore/reset rotates generation explicitly; restored content alone cannot detect backup rollback. Add explicit restore operational contract before claiming old token safety across restore.
5. Signed project path metadata filtering remains sender-host scoped classification. Recipient permission always checked independently before limit/count/cursor; an advertised topic or capability cannot subscribe, grant access or instantiate role instructions. Portable mappings and historical catch-up remain separately authorized tasks. Filter metadata projection never rewrites envelope/signature.
6. Console bootstrap must distinguish initial navigation GET (normally no Origin) from same-origin bootstrap POST requiring exact Origin plus launch capability. Private cookie endpoints without Origin cannot inherit implicit trust for arbitrary native callers; use explicit capability route contract. Owner launch authorization needs concrete local mechanism, not mere `--owner` flag or agent filesystem capability. Cross-origin fetch, wrong Host, DNS rebinding, expired bootstrap and replayed fragment must fail. Render mail as escaped text; no executable HTML/Markdown URL fetches, remote images or secrets in errors/export/logs. API viewing preserves state. SEA/static packaging must be verified against actual build embed paths; C4 listed hypothetical scripts/check-dist.mjs is not an existing guaranteed integration point.
7. Discovery preview is native metadata, not a conforming A2A AgentCard if required executable-interface fields cannot honestly be populated. Label representation/protocol explicitly; no placeholder execution URL or advertised streaming/task cancellation. Authenticated immutable principal is mandatory for production CLEO transport; ACK is mailbox acknowledgement, never processed/completed. Deduplicate transport event IDs separately from task-authorized evidence. License matrix correctly separates MIT code, AutoGen CC-BY documentation and Apache schemas; any actual copy needs exact source/modification/notice provenance.

## Executable acceptance cases

- Two concurrent writers deliver equal timestamp/backdated envelopes and late fanout: replay authorized IDs exactly once in visibility order, including events after initial snapshot on next poll.
- Rename pending A->B with B already recipient/acked: no duplicate B event and no ACK resurrection; old-name cursor cannot expose removed pending rows; exact lease authorization rechecked. Inject mail-transfer failure and assert documented lease result, no silent loss.
- Filtered page with200hidden/out-of-project entries before one visible row: bounded progress, no foreign IDs/counts, no infinite empty cursor; oversized visible body returns deterministic bounded outcome.
- Reuse same input cursor after lost response while new mail arrives: same snapshot range; completed token discovers only later visible events. Foreign mailbox, modified filter, tampered token, fenced lease rejected; same persona new provider lease resumes safely.
- Store migration: deterministic backfill, rollback on injected error, signed envelope bytes/ACKs unchanged, old writers fail closed, explicit restored generation rejects old token. Read-only APIs hash relevant state before/after including pending receipt and lease timestamps.
- Candidate pending index: malformed/scalar/null/array/non-control KV, missing control key, expired/pending/completed states; equivalent valid controls and safe insert/update, exact EXPLAIN index usage. Sender index retains multi-peer COUNT DISTINCT and benchmark write/storage/skew limits. Index-only migration need not pretend incompatible schema if old writers remain correct; ledger migration does require fencing.
- Console foreign Origin/wrong Host/LAN/unauthenticated/expired/replayed bootstrap denied; initial navigation allowed without leaking private state; owner-selected browsing does not acknowledge or claim. Secrets injected into errors/envelopes never reach metadata/export unless explicitly selected bounded body export.
- A2A capability import tampered/expired/oversized/unsupported: no network fetch/tool execution/authority change; preview omits unsupported execution semantics. CLEO payload.taskId or mbx_ack leaves task completion unchanged.

## Disposition and limitations

Review is conditional consensus, not implementation acceptance. Incorporate boundary and caller clarifications in integration spec before R1. T119 synthetic macOS SQL measurements are real but not proof of concurrent writers, provider wake storms, Linux/Windows parity or index write overhead. AgentMBX cross-platform release gate currently macOS/Linux; Windows remains unsupported until separate process/private-file evidence. Keep research/task statuses partial where product gates and runtime evidence are absent. No product code, upstream copy, commit or owner question performed by this review.
